# MotionBricks Blender 优化实施方案

本文记录早期实施计划。当前版本功能和安装方式见 [README](../README.md) 与 [更新记录](../CHANGELOG.md)。

## 目标与现状

把动作来源、姿势编排和补间结果串成一个 Blender 工作流。用户可以导入 BVH 或 MotionBricks 录制，播放并取帧，把同一个姿势放到场景里的不同位置和朝向，再生成可继续编辑的 Blender Action。路线行走和场景工具按需展开，主侧栏以目标序列为中心。

当前基线是插件 0.1.5、Blender 5.1.2 Linux、MotionBricks 0.2.0 和 SOMA FP16。现有插件已经支持 BVH 预览、姿势资产、目标排序、全序列视口预览和多段补间。目标位置来自保存时的根节点坐标，侧栏和视口目前提供查看。

参考版的 Recorder 已在现有环境录制 90 帧，Walker 的 Zigzag 已生成 564 帧并在 Blender 重开。把同一份录制的原始姿势重新烘焙到我们的 SOMA 骨架后，抽检帧的网格与参考版相差约 8 微米。直接指派参考版 Action 时会出现明显变形。因此，集成走原始姿势到当前 RigAdapter 的转换路径。 [本插件说明](../README.md) · [参考项目](https://github.com/hyun2xyz/motionbricks-blender) · [MotionBricks 0.2.0](https://github.com/NVlabs/motionbricks/releases/tag/v0.2.0)

## 一、界面与操作流程

| 入口 | 常驻操作 | 按需展开 |
| --- | --- | --- |
| **目标序列** | 视口预览、生成补间、起始项、目标列表、添加和排序 | 选中项的世界坐标、朝向、相对上一项的位移、保留动势、恢复原位 |
| **动作库** | 搜索、选择、播放、暂停、逐帧、保存当前姿势 | BVH 动作包、导入的 NPZ 录制、插件生成的 Action、来源与时间 |
| **姿势资产** | 选姿势、设为起始、添加目标、应用到角色 | 分类、来源、原始位置和采样信息。单帧资产可从 Blender Asset Browser 浏览 |
| **路线行走** | 选曲线或导入路线 JSON、设置速度、生成 | 起止朝向、停留时长、诊断信息 |
| **角色与场景** | 选择或创建参考角色 | 导入布景、构建跟拍相机、导出录制、环境诊断 |

- **从动作取帧。** 在同一个预览入口播放 BVH、录制或生成结果。显示来源、原始帧率和当前时间。暂停或逐帧后可以直接保存。连续动作默认提供“同时采样相邻帧”的选择，手动摆的姿势可保存为单帧。退出预览时恢复原 Action、播放范围与时间位置。
- **在视口摆位。** 点击列表或视口标记选择起始姿势或目标，拖动平移手柄和绕 Z 轴的旋转手柄。侧栏数值与视口实时同步，并提供一键恢复原位和撤销。世界位置接近时可切换“只看选中”，便于判断肢体形态。 [Blender GizmoGroup API](https://docs.blender.org/api/5.0/bpy.types.GizmoGroup.html)
- **检查并生成。** 在视口按实际坐标展示所有姿势。序列连线表示目标顺序。生成完成后，播放真实输出 Action，查看各段的实际到达帧。输出支持选择写入的起始帧，并保留已有 Action 供切换。
- **保持侧栏紧凑。** 沿用 0.1.5 的独立子面板，默认展开目标序列。动作源、路线和布景功能折叠显示。交互、数据和推理各有单独模块，面板只负责呈现状态和发起操作。

## 二、技术设计

### 动作导入与时间轴

第一阶段支持参考版 `motionbricks-blender-npz` v1，入口为“文件 → 导入 → MotionBricks 录制”和动作库中的“导入录制”。默认模式把录制烘焙成**当前 SOMA 角色**的新 Action，导入后可进入预览。后续增加“创建新角色和场景”模式，用于在空工程打开完整录制。

1. 在创建 Blender 数据前检查文件标识、格式版本、尺寸上限、关节名称和父子关系、单位与坐标变换、绑定矩阵及浮点数有效性。以 `allow_pickle=False` 读取。关节顺序不同但同名且层级、坐标和绑定可核验时，可显式重排。其它骨架明确提示不兼容。
2. 统一使用 SOMA 姿势约定。根节点为 Z 向上的世界坐标，单位为米。子关节变换相对父节点。录制的 `model_to_runtime` 用于核对坐标约定，运行时姿势已经处于对应坐标系，转换一次即可。
3. 用源时间和工程帧率计算关键帧，`frame = start + t × fps / fps_base`。例如 30 fps 的录制导入 24 fps 工程时仍按真实秒数播放。通过 RigAdapter 批量写 Action Slots 和 F-Curves。长片段分批处理，解析或验证失败时清理临时数据，保留已有工程内容。
4. 在新 Action 上保存来源类型、文件名、源帧率和格式版本等必要信息。导入完成后，动作随 `.blend` 持久化，重开时可从动作库再次播放。预览、取帧和退出统一走已有的预览生命周期。 [参考版 NPZ 读取与校验](https://github.com/hyun2xyz/motionbricks-blender/blob/main/addon/motionbricks_importer/importer.py#L101) · [RigAdapter](../motionbricks_blender/rig.py#L139)

### 姿势资产与摆位

现有姿势资产继续保存捕获时的姿势，以及可选的前后采样窗口。**位置与朝向编辑写入序列项**。起始项和每个目标项分别存储平移偏移、绕 Z 轴的角度和动势选项。同一份姿势资产可以添加多次，分别摆在不同位置。旧工程中缺失的偏移和角度按零处理。

用捕获锚点 `a`、根节点位置 `p`、根旋转 `q`、平移 `Δ` 与绕 Z 轴的旋转 `R` 计算新的根节点变换。

```text
p_new = a + R × (p - a) + Δ
q_new = R × q
```

旋转围绕该姿势自身的根节点。对保留动势的采样窗口，每一帧都用同一个锚点和变换，这样转向时速度方向也跟着旋转，子关节局部变换不受摆位影响。视口、数值面板与生成请求共用这套计算。预览可以复用缓存的蒙皮几何，在拖动时先更新整体变换，以保持交互流畅。

### 生成与任务边界

- 沿用 `jobs.py` 的本地子进程和 Blender 定时器。任务从不可变的输入快照开始，记录骨架签名、姿势版本、摆位参数与帧率。返回时核对场景和角色，生成结果以独立 Action 提交。进度区分加载引擎、推理、烘焙。取消、场景切换、运行失败均清理临时任务。
- 延续当前 MotionBricks 的 30 Hz 输入约定。起始使用四帧上下文，静止目标用一帧，保留动势目标用已有的后续采样。相邻生成段共享端点，标记使用后端返回的实际段尾。规划界面先提供起始帧和输出时长，精确指定过渡时长可另立功能，先验证模型约束与重定时对落脚的影响。
- 短任务先沿用版本化 JSON 控制协议。长序列在实测内存或解析成本达到瓶颈时，将姿势数组换成独立二进制载荷，任务状态和元数据仍由 JSON 表达。NPZ 是可交付的交换文件，临时任务结果按需精简。
- 逐步把侧栏和 UIList 移到 `ui`，把录制读取、序列摆位和路线输入分别做成可单测的模块。保留现有 Blender Operator ID、场景属性入口和骨架签名。先通过测试固定现有行为，再随功能迁移对应代码。 [任务管理](../motionbricks_blender/jobs.py) · [补间后端](../motionbricks_blender/backend.py#L83)

### 路线与场景扩展

- **路线行走。** 沿用参考版“站姿生成初步步态 → 提取模板 → 沿路点连续生成”的方法。先兼容 Zigzag、Heart 的路线 JSON，再接 Blender 曲线取样。初期使用 XY 平面路点和显式起止朝向，场景方块作为可见布景，绕行通过路线设计实现。参考版使用 FP32。接入时先用原版作为对照，验证现有 FP16 的终点误差和步态质量，再决定默认精度。输出进入同一个动作库，可接着取帧或用于补间。 [Walker 源码](https://github.com/hyun2xyz/motionbricks-blender/blob/main/walker/mb_walk.py#L147)
- **录制。** 优先接收外部 Recorder 产出的 NPZ。若确实需要从 Blender 启动录制，再增加单独入口并固定 MotionBricks API 版本。参考实现访问 Scene Preview 的内部会话对象，相关兼容代码隔离在外部适配层。 [Recorder 源码](https://github.com/hyun2xyz/motionbricks-blender/blob/main/recorder/mb_record.py#L137)
- **交换与布景。** 导出兼容 v1 的完整录制，携带源信息、真实绑定和蒙皮数据。新角色与布景导入放到独立 Collection。地板、灯光、跟拍相机分别可选，接管场景相机或更改工程帧率由用户显式选择。参考版的 `make_demo.py` 可作为批量生成渲染工程的验证工具。 [示例构建脚本](https://github.com/hyun2xyz/motionbricks-blender/blob/main/tools/make_demo.py)
- **样例与扩展范围。** 首批功能以 SOMA 为基线。自定义骨架重定向、G1 和 Smart Primitives 在基础流程稳定后按各自的模型和骨架契约规划。发布示例采用程序生成路线或授权动作。涉及官方样例动作的测试依照其评估许可管理。 [NVIDIA 样例动作许可](https://github.com/NVlabs/motionbricks/blob/v0.2.0/assets/motions/LICENSE.txt)

## 三、实施顺序与验收

版本号为建议的交付批次。每批独立构建安装包，在 Blender 5.1.2 的隔离配置中验证从上一版覆盖安装。

| 批次 | 交付内容 | 验收条件 |
| --- | --- | --- |
| **0.2 · 动作互通** | NPZ v1 导入当前 SOMA、动作库统一预览与取帧、导入来源信息 | 90 帧录制和 564 帧 Zigzag 均可导入、播放、暂停取帧并生成补间。在 24、30、60 fps 工程中保持时间一致。抽检帧的蒙皮顶点误差不超过 0.2 mm。错误或不兼容文件导入失败后，现有场景与 Action 可正常使用。 |
| **0.3 · 视口编排** | 起始和目标的独立 XYZ/朝向、数值编辑、视口手柄、选中隔离、撤销 | 同一姿势两次入列可以分别移动。旋转带动相邻采样帧的运动方向。重排后各项保持自己的摆位。预览锚点和提交给后端的锚点一致。保存并重开后可继续编辑，0.1.5 的旧工程按原坐标显示。 |
| **0.4 · 路线行走** | JSON 路线、Blender 曲线输入、速度与起止朝向、独立任务进度和取消 | 在 Zigzag 和 Heart 测试路线中跑完全程。建议的验收目标是根节点距终点不超过 0.15 m，停步末段平均水平速度低于 0.1 m/s，使用模型输出帧测量。走路结果可播放、取帧、保存重开。空路线、零速度、过密路点或取消都有明确结果。FP16 与 FP32 对照通过后确定默认精度。 |
| **0.5 · 交换与场景** | NPZ 导出、新角色与布景导入、可选跟拍相机 | 本插件导出的 NPZ 可被参考版导入并正确播放。布景进入独立集合。导入选项能保留现有相机和工程时间设置。导出的动作来源信息可读。 |

每批运行现有 Blender 冒烟测试，回归 USD 骨架、蒙皮、动作预览恢复、姿势资产和两段补间。新功能按需增加小样本单元测试和 Blender 集成测试。界面验收使用默认窄侧栏、空场景和已有工程，覆盖关闭预览、撤销、取消和重新加载。

首个开发切片以“导入一份录制 → 在现有角色上预览 → 保存一帧 → 加入目标序列 → 生成补间”为准。这个切片可以直接用现成的 90 帧录制和 Zigzag 验证，也为下一批的摆位和路线功能提供共同的动作入口。
